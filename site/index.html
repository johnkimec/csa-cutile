csa
Compression Indexer Attention Cache

DeepSeek-V4 §2.3, drawn as the PyTorch reference implements it

Compress every m tokens. Attend to k of the results.

Compressed Sparse Attention keeps one KV entry per block, not one per token. Each query scores those entries with a small indexer and reads only the top k, plus a short window of the tokens it just wrote.

The two streams overlap on purpose.

Each token is projected twice. The a-stream belongs to the block it sits in. The b-stream is saved for the next block. A softmax over those 2m positions, per channel, weights the values.

A cheap score picks the k blocks.

The indexer does not run full attention. A shared low-rank vector makes the indexer queries, a separate projection makes a weight per head, and the score is a ReLU dot-product. Only finished blocks to the left are visible.

Core attention reads two kinds of KV.

The selected compressed entries are the long-range memory. A sliding window of the last n_win uncompressed tokens, including the current one, covers the block the indexer is not allowed to see. One shared KV head serves every query head.

The cache emits a block one token late.

Decoding does not recompress the whole sequence. It keeps the unfinished block, the previous b-stream, the compressed entries, and the sliding window. The block becomes visible only after the token that filled it has already attended.

Greyscale notes for the pure-PyTorch module. Triton, cuTile, and a long-context model run are not drawn, because this tree does not implement them yet.
